# Triage issues

1. List open issues for the repository, newest first, unless the user narrows it (label, milestone, author).
2. For each issue, read the body and comments, then check the code: does the bug still exist on the default branch? Is the feature already there?
3. Group duplicates and name the issue to keep.
4. Propose, per issue: a label, a priority (with one line of reasoning), and a next step (close as fixed, needs repro, ready to build, duplicate of #n).
5. Show the proposal as a table. Change labels, comment or close only after the user confirms, and quote the issue number in every action.
