# File a Linear issue

1. Pick the team: ask if the workspace has more than one and the repository does not make it obvious.
2. Search for an existing issue first; if one matches, add a comment there instead.
3. Write the issue:
   - Title: what is wrong or what to build, in plain words.
   - Description: steps to reproduce or the motivation, expected and actual behaviour, and file paths with line numbers from this repository.
   - Include error messages verbatim. Leave out secrets, tokens and customer data.
4. Set priority and labels only when the user gave them or the team's conventions make them clear.
5. Show the draft, create it after the user agrees, and reply with the identifier and link.
